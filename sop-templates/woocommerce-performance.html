⚡ WooCommerce Performance Optimization

Mục đích: Giảm thiểu high load, HTTP 500 errors, và swap usage trên WooCommerce sites. Áp dụng khi server có dấu hiệu quá tải hoặc search gây crash.

1. Search Engine — Replace WooCommerce Native Search

Search là nguyên nhân số 1 gây high load trên WooCommerce. Native search dùng MySQL LIKE queries phức tạp + filter attributes → PHP timeout → 500 errors → lsphp workers stuck.

Option A: Typesense (Recommended)

# Install
apt-get install typesense-server

# Config (/etc/typesense/typesense-server.ini)
api-key = <generate via: openssl rand -hex 32>
data-dir = /var/lib/typesense
api-port = 8108
api-address = 127.0.0.1

# Restart
systemctl restart typesense-server

# Install WP plugin
wp plugin install search-with-typesense --activate
wp option update cm_typesense_admin_settings '{...}' --format=json
wp typesense index product

Option B: Relevanssi Premium

wp plugin install relevanssi --activate
# Premium version supports WooCommerce product search weighting

2. MariaDB Tuning

InnoDB buffer pool thường được set quá cao, gây swap. Công thức: 20-25% tổng RAM, tối đa 2GB trên shared server.

# /etc/mysql/mariadb.conf.d/99-custom.cnf
[mysqld]
innodb_buffer_pool_size = 1536M    # 1.5GB cho server 7.8GB RAM

# Apply
systemctl restart mariadb

# Chú ý: Không dùng giá trị thập phân (vd: 1.5G)
# MariaDB chỉ chấp nhận integer suffix: 512M, 1G, 1536M

3. Bot & Scanner Blocking

Chặn bot crawl search pages và scanner probing để giảm tải:

# .htaccess — block bot search access
RewriteCond %{QUERY_STRING} (^|&)s= [NC]
RewriteCond %{HTTP_USER_AGENT} (Googlebot|bingbot|GoogleOther) [NC]
RewriteRule .* - [R=403,L]

# Block scanner IPs
RewriteCond %{REMOTE_ADDR} ^20\.226\.26\.5
RewriteRule .* - [R=403,L]

4. ClamAV CPU/IO Limit

Security audit ClamAV scan có thể gây CPU 100% trên server có uploads lớn.

# Trong wp-security-audit.sh — wrap clamscan với nice + ionice:
ionice -c 2 -n 7 nice -n 19 clamscan -r "$SCANPATH" --bell -i \
  --exclude-dir="^$SCANPATH/wp-content/cache" \
  --max-filesize=100M --max-scansize=200M

5. WP-Cron Frequency

Kiểm tra và giảm tần suất wp-cron nếu quá frequent:

# Kiểm tra crontab của runcloud user
crontab -u runcloud -l

# Các mức tần suất nên dùng:
# */5   → quá frequent, cần giảm
# */10  → chấp nhận được
# */30  → khuyến nghị cho WooCommerce site
# 0 *   → mỗi giờ, phù hợp cho site ít cập nhật

7. Kiểm tra định kỳ

# Kiểm tra swap
free -h
swapon --show

# Kiểm tra MariaDB memory
ps aux | grep mariadb | awk '{print $6/1024 " MB RSS"}'

# Kiểm tra lsphp workers
pgrep -c lsphp
ps aux --sort=-%rss | grep lsphp | head -5

# Kiểm tra 500 errors
grep ' 500 ' /path/to/access.log | wc -l
awk '$9 == 500 {print $7}' access.log | sort | uniq -c | sort -rn | head -5
