🔒 Fail2ban Unban IP

Mục đích: Quy trình kiểm tra và unban IP bị fail2ban block trên server, áp dụng khi team không SSH được vào server do IP bị ban nhầm.

1. Kiểm tra trạng thái fail2ban

Trước khi unban, xác nhận IP thực sự bị ban bằng cách kiểm tra jail liên quan:

# Kiểm tra tất cả jail
sudo fail2ban-client status

# Kiểm tra jail sshd (phổ biến nhất)
sudo fail2ban-client status sshd

# Kiểm tra jail sshd-ddos (nếu có)
sudo fail2ban-client status sshd-ddos

# Kiểm tra banned IP list
sudo fail2ban-client banned

2. Unban IP

Xoá IP khỏi jail bằng lệnh sau (thay xxx.xxx.xxx.xxx bằng IP cần unban):

# Unban khỏi jail sshd
sudo fail2ban-client set sshd unbanip xxx.xxx.xxx.xxx

# Unban khỏi jail sshd-ddos (nếu có)
sudo fail2ban-client set sshd-ddos unbanip xxx.xxx.xxx.xxx

# Unban khỏi jail runcloud-agent (nếu có)
sudo fail2ban-client set runcloud-agent unbanip xxx.xxx.xxx.xxx

⚠️ Lưu ý: Không ghi lại IP cụ thể trong báo cáo hay document — chỉ unban và kết thúc. Unban cần chạy riêng trên từng server (fail2ban không sync giữa các máy). Sau unban kiểm tra lại bằng sudo fail2ban-client status sshd — IP không còn trong banned list.

3. Kiểm tra nguyên nhân bị ban

Xác định lý do IP bị ban từ log:

# Kiểm tra fail2ban log
sudo grep 'xxx.xxx.xxx.xxx' /var/log/fail2ban.log

# Kiểm tra auth log — xem failed attempts
sudo grep 'xxx.xxx.xxx.xxx' /var/log/auth.log | tail -10

# Kiểm tra journal (nếu dùng systemd)
journalctl -u sshd --no-pager | grep 'xxx.xxx.xxx.xxx'

Ghi chú: auth.log và journal có thể bị rotate. Nếu không tìm thấy log, kiểm tra file log cũ (auth.log.1, auth.log.2.gz) bằng zcat.

4. Debug SSH kết nối

Nếu vẫn không SSH được sau khi unban, kiểm tra thêm:

# Kiểm tra IPTABLES còn block không
sudo iptables -L INPUT -n --line-numbers

# Kiểm tra ufw (nếu dùng)
sudo ufw status

# Kiểm tra fail2ban iptables chain
sudo iptables -L f2b-sshd -n

5. Phòng ngừa

  • Luôn SSH bằng public key, không dùng password.
  • Kiểm tra SSH config local trước khi connect hàng loạt (script/cron) — sai user có thể gây failed attempts hàng loạt, kích hoạt fail2ban.
  • Nếu có automation (cron job, health check) chạy SSH hàng loạt, cân nhắc whitelist IP nguồn trong fail2ban.
